# 📋 LangGraph 消息压缩架构与执行计划 (Comprehensive Implementation Blueprint)

## 一、 核心架构目标

实现一套兼具**上下文防爆、记忆连续、安全降级、零位置错位**的长文本对话消息滚动压缩（Rolling Summary）机制，确保 LangGraph 在长周期交互下的稳定高效。

---

## 二、 核心步骤实施计划

### 步骤一：判定是否需要压缩（Gating & Batch Rules）

在每次对话或图节点入口处，通过“基础校验 + 双门控联动 + 溢出兜底”决定是否启动压缩：

1. **基础前置校验**：确保消息列表非空，且总轮次大于无条件保留的最近轮次（`keep_last_turns`），否则直接跳过。
2. **双门控核心判定（同时满足时触发）**：
* **轮数门控**：当前对话总轮次 $>$ 保留轮次。
* **字符数门控**：可压缩区域内的字符总量 $\ge$ 默认字符阈值（`threshold_chars`，如 1,200,000）。


3. **溢出强触发兜底（Max Compressive Limit）**：
* 若待压缩的历史消息条数 $\ge$ 最大压缩消息批次上限（`max_compressive_messages`），则绕过字符阈值限制，**强制触发极限压缩**（除系统消息和最近保留轮次外，历史区域所有消息全部压缩）。


4. **豁免保护**：静态系统提示词（System Prompt）与既有滚动摘要不参与字符统计与常规裁剪。

---

### 步骤二：处理压缩内容并使用 LLM 汇总（Content & LLM Summarization）

当判定触发压缩后，将划定好的旧历史区间交由大模型进行智能迭代：

1. **输入数据组装**：
* 提取并定位历史中已存在的滚动摘要（作为既有记忆）。
* 遍历待压缩的历史原文区间，严格应用可压缩过滤规则，渲染出干净的时序文本流。


2. **LLM 增量迭代提示词**：
* 采用“既有滚动摘要 + 新历史原文”的双输入结构。
* 约束 LLM 提取核心技术栈、架构决策、用户意图及未竟事项，并以最新结论覆盖旧方案，剔除对话泡沫。


3. **防御性异常降级（Safe-Skip）**：
* 捕获大模型调用过程中可能发生的异常。
* **核心契约**：若大模型报错或返回空值，必须平稳返回空标识并记录错误日志。上层感知后**直接中止本轮压缩计划，绝不删减任何消息**，确保用户历史 100% 安全。



---

### 步骤三：LangGraph 消息状态更新与原地替换（In-Place State Mutation）

利用 LangGraph 的消息状态管理能力，实现高效、无序位错乱的底层状态变更：

1. **精准物理删除（Purge Old Raw Messages）**：
* 遍历本轮计划压缩的旧消息区间，为每一条合格的消息生成 `RemoveMessage(id=...)` 指令（系统消息享受白名单保护，绝对不删）。


2. **原地锚定置换（In-Place Substitution）**：
* 在被裁剪的旧消息区间内，精准选中第一条用户输入消息（`HumanMessage`）作为历史时间轴锚点。
* 将该锚点消息同样加入 `RemoveMessage` 列表，并在此位置无缝注入带有滚动摘要书签前缀（`SUMMARY_BOOKMARK_PREFIX`）的最新摘要内容。
* **优势**：滚动摘要自然继承了原先旧消息在列表中的先后顺序和时间轴位置，彻底省去全局消息排序重排的烦恼。
