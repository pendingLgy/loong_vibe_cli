# 💻 Skill: Code Generation & Implementation (代码生成与实现)

## 🎯 触发场景
当用户提出以下类型的需求时，必须优先启用此技能：
1. 要求从零编写新的代码文件、类、函数或完整模块。
2. 要求对现有代码进行深度重构、性能优化或架构升级。
3. 需要为特定功能补充配套的单元测试或接口调用示例。

---

## 📝 核心工作流规范

在动手生成代码时，你必须严格遵循以下工程化标准：

### 阶段一：设计与规范确认 (Design & Standards)
1. **技术栈与上下文对齐**：自动或通过已有工具识别当前工作区的技术栈（如 Python/FastAPI、TypeScript/React 等），遵循项目现有的代码风格、命名规范和依赖库版本。
2. **安全与边界检查**：确保生成的代码严格限制在工作区 `work_dir` 内，禁止引入存在安全隐患的硬编码凭证或高危系统调用。

### 阶段二：高质量代码生成 (Code Construction)
1. **模块化与单一职责**：编写高内聚、低耦合的代码，避免出现单文件代码过长（God File）的现象。
2. **异常处理与日志**：在关键业务逻辑、外部服务调用、I/O 操作处必须加入健壮的异常捕获（Exception Handling）和结构化日志记录。
3. **跨平台兼容性**：若涉及文件路径、Shell 命令或系统资源操作，必须考虑跨平台（Windows / Linux / macOS）兼容性。

### 🎨 编码风格与规范 (Coding Style & Guidelines)
1. **类型提示与文档 (Types & Docs)**：
   - 所有函数/方法必须包含清晰的参数和返回值类型注解（Type Hints）。
   - 核心类和复杂函数必须提供简洁的 Docstring（说明其用途、参数及返回值）。
2. **命名规范 (Naming Conventions)**：
   - 遵循主流语言惯例（如 Python 的 `snake_case` 用于函数/变量、`PascalCase` 用于类名；TypeScript 的 `camelCase` 等）。
   - 严禁使用毫无语义的单字母变量（循环计数器除外），确保代码具备极高的自解释性。
3. **现代语法与整洁代码 (Modern Syntax & Clean Code)**：
   - 优先使用现代语言特性（如 Python 的 `pathlib` 替代旧版 `os.path`、使用类型联合符 `str | None` 等）。
   - 保持代码缩进统一、行宽适中，禁止留下大段无用的注释或调试代码 (`print`/`console.log`)。
4. **务实边界与人工接力 (Pragmatic Boundaries)**：
   - 不要过度追求完美的极端边缘情况（Edge Cases）约束或过度设计。针对复杂的业务兜底或非核心异常分支，可保持代码清爽精炼，适当将复杂的边界处理留给人工在后续迭代中二次完善。

*📌 代码输出格式规范*：
- 必须使用标准的 Markdown 代码块包裹，并标明语言类型（如 ```python, ```typescript）。
- 若涉及多文件修改或新增，需在代码块上方或下方清晰标注其对应的**相对文件路径**。

### 阶段三：自测与验证引导 (Verification)
1. 代码输出后，主动提示用户进行必要的静态检查或单元测试验证。
2. 如果项目配置了对应的 Lint 或格式化工具（如 Black、Ruff、Prettier），提示用户执行。

---

## 🚫 行为禁忌 (Don'ts)
- ❌ **严禁凭空盲写**：禁止在完全不了解项目上下文或已有依赖的情况下，盲目生成大量无法运行的孤立代码。
- ❌ **严禁缺少类型与注释**：禁止编写没有任何类型提示或关键说明的“野蛮生长”式代码。
- ❌ **严禁过度设计**：禁止为极低概率发生的边缘情况堆砌过于繁琐的防范代码，导致核心逻辑臃肿。
- ❌ **严禁越权操作**：禁止生成任何尝试读写工作区外部敏感系统文件的代码。
