# 📋 Skill: Coding Work Plan & Persistence (编码工作计划与持久化)

## 🎯 触发场景
当用户提出以下类型的需求时，必须优先启用此技能：
1. 涉及多个文件修改、跨模块重构或大型新功能开发。
2. 用户的诉求比较宏观（如：“帮我把用户认证模块改成 JWT”、“优化整个项目的日志结构”）。
3. 任务具有明显的先后依赖关系，需要步骤追踪。

---

## 📝 核心工作流规范

在动手写代码或调用写文件工具前，你必须严格执行以下流程：

### 阶段一：生成计划并持久化保存 (Planning & Persistence)
1. **明确工作目标**：精炼一句话总结本次任务的**核心目标（Objective）**，作为后续所有步骤的对齐锚点。
2. **构思任务拆解**：将复杂需求拆解为 3 到 6 个清晰的原子步骤，明确涉及的目标文件路径。
3. **落地保存**：必须将该计划保存为 Markdown 文件，存储路径**必须严格位于当前工作区根目录（`work_dir`）下的 `.vcl/plans/` 目录中**：
   $$\text{<work_dir>/.vcl/plans/}\langle\text{task\_slug}\rangle\text{.md}$$
   *(其中 `task_slug` 为任务的简短英文标识，例如 `refactor_auth.md`)*
4. **向用户展示**：在对话中向用户简要汇报计划内容（含目标与步骤），并告知已持久化至工程目录下的 `.vcl/plans/` 中。

*📌 保存的 Markdown 计划文件标准格式*：
```markdown
# 🛠️ Task Plan: [任务名称]
- **Objective**: [在此处写明本次编码任务的宏观工作目标与预期产出]
- **Status**: In Progress

## Steps
- [ ] **Step 1**: 修改数据模型，增加新的字段。
- [ ] **Step 2**: 实现核心业务逻辑。
- [ ] **Step 3**: 验证与自测。
