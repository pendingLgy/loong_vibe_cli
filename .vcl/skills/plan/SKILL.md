# 📋 Skill: Coding Work Plan & Persistence (编码工作计划与持久化)

## 🎯 触发场景
当用户提出以下类型的需求时，必须优先启用此技能：
1. 涉及多个文件修改、跨模块重构或大型新功能开发。
2. 用户的诉求比较宏观（如：“帮我把用户认证模块改成 JWT”、“优化整个项目的日志结构”）。
3. 任务具有明显的先后依赖关系，需要步骤追踪与测试场景对齐。

---

## 📝 核心工作流规范

在动手修改代码或调用文件编辑工具前，你严格执行以下流程：

### 阶段一：生成计划并持久化保存 (Planning & Persistence)
1. **明确工作目标**：精炼一句话总结本次任务的**核心目标（Objective）**，作为后续所有步骤的对齐锚点。
2. **构思宏观业务步骤**：将复杂需求拆解为 3 到 6 个清晰的原子步骤，列出涉及的核心模块或目标文件路径。
   * **注意**：仅规划核心业务逻辑与数据流向，**切勿深入具体实现细节**（细节留待后续人工审查代码时调整）。
3. **设计测试用例场景**：基于业务逻辑输出关键的**测试用例场景（Test Scenarios）**，供人工审查及后续验证使用。**不得包含任何自动运行测试或自测步骤**。
4. **落地保存**：必须将该计划保存为 Markdown 文件，存储路径**必须严格位于当前工作区根目录（`work_dir`）下的 `.vcl/plans/` 目录中**：
   $$\text{<work_dir>/.vcl/plans/}\langle\text{task\_slug}\rangle\text{.md}$$
   *(其中 `task_slug` 为任务的简短英文标识，例如 `refactor_auth.md`)*
5. **向用户展示**：在对话中向用户汇报计划内容（目标、宏观步骤与测试场景），并告知已持久化保存。待人工审查代码并确认无误后，再根据需要进行手动或自动化验证。

---

*📌 保存的 Markdown 计划文件标准格式*：

```markdown
# 🛠️ Task Plan: [任务名称]
- **Objective**: [在此处写明本次编码任务的宏观工作目标与预期产出]
- **Status**: In Progress

## 1. 核心业务步骤 (Business Steps)
*(注：仅梳理大体业务逻辑与模块变更，具体实现细节由人工查阅代码调整)*
- [ ] **Step 1**: [模块/文件路径] 调整核心数据结构/模型接口。
- [ ] **Step 2**: [模块/文件路径] 搭建主干业务流逻辑与异常抛出分支。
- [ ] **Step 3**: [模块/文件路径] 补全上层服务或 API 接口调用契约。

## 2. 测试场景设计 (Test Scenarios)
*(待人工调整确认代码无误后，再执行手动或自动化测试)*
- [ ] **Scenario A (正向用例)**: [描述正常业务流的输入与期望输出]
- [ ] **Scenario B (边界/异常用例)**: [描述异常参数或状态下的预期响应]
